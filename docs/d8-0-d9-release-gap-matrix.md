# D8.0 to D9 release gap matrix

## Reading this matrix

This is the release decision record for taking the D8.0 adoption contract into
D9.  It covers a new worktree, an existing clean worktree, an existing dirty
worktree, and cross-journey behaviors that must be consistent for all three.
`MUST FIX BEFORE D9 RELEASE` is a release blocker.  `CAN FIX AFTER D9 RELEASE`
is deliberately non-blocking only after its named D9 gate has passed.

`AUDITED-GAP` means repository evidence demonstrates a mismatch.  `CONTRACT-DEFINED`
means the D8.0 contract defines the behavior but this audit has not
located a D9 implementation proof.  `PENDING-EVIDENCE` means a necessary fact
was not found and must be supplied; it is not an assumption or a pass.

## D9 release decision rule

D9 is not releasable until every `MUST FIX BEFORE D9 RELEASE` row has passed
its named gate and every `PENDING EVIDENCE` row has been resolved with the
specified operator evidence and a subsequent disposition.  A `CAN FIX AFTER
D9 RELEASE` row remains non-blocking only while its stated non-semantic scope
is preserved.
